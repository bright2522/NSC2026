────────────────────────────────────────────────────────────────────────────────
EVENT 1 — ร่อนกระทะ (Flick phone → pan toss/flip)
────────────────────────────────────────────────────────────────────────────────

Concept
  ผู้เล่น "ร่อน" มือถืออย่างรวดเร็ว 1 ครั้ง → กระทะ flip/กระเด้งของในกระทะ
  ใช้ตอน Cooking phase (เช่น หลังของเริ่มสุก ต้องร่อน 1-2 ครั้ง)

ความต่างจาก shake ใน CookingState ปัจจุบัน
  |           | Shake (มีแล้ว)              | Flick (ต้องทำ)                |
  |-----------|-----------------------------|-------------------------------|
  | Input     | |accel| สูงต่อเนื่อง        | delta accel สูงช่วง < 0.3s    |
  | จุดประสงค์ | bonus ความสุกต่อเนื่อง      | trigger flip ครั้งเดียว       |
  | Score     | partial bonus               | timing ใน ideal window        |

ไฟล์ที่ต้องสร้าง
  pep/Scripts/Input/FlickDetector.cs
  pep/Scripts/Minigames/Cooking/PanFlickMinigame.cs

FlickDetector.cs — logic หลัก
  - เก็บ accel ย้อนหลัง 5-10 frame (ring buffer)
  - jerk = (accelNow - accelPrev) / dt
  - OnFlickDetected(Vector3 direction, float intensity) เมื่อ |jerk| > flickThreshold
  - cooldown 0.4s กันยิงซ้ำ
  - calibrate: ลบ gravity baseline ตอนเริ่ม minigame (Input.acceleration ตอนมือถือนิ่ง)
  - Editor: GetKeyDown(Space) หรือ mouse flick แทน

PanFlickMinigame.cs — minigame
  - Implements sub-step หรือ MonoBehaviour แยกที่ CookingState เรียก
  - State: WaitingFlick → Flicked → Scored
  - แสดง UI mock: "ร่อนมือถือเพื่อพลิกกระทะ!" + progress ว่าร่อนแล้วกี่ครั้ง
  - ideal window: หลัง cookProgress ถึง X% ภายใน Y วินาที (คล้าย coco/GrillingMinigame flip timing)
  - score: 100 ใน ideal, ลดลงถ้าร่อนเร็ว/ช้าเกิน, 0 ถ้าไม่ร่อนก่อนหมดเวลา
  - event: OnPanFlickCompleted(float score, bool success)
  - ส่งคะแนน: ScoringManager.ReportStepScore("pep/PanFlick", "Pan Flick", score)

Optional (ทีม art / scene — out of scope PEP)
  - Transform pan หมุนรอบ X axis เมื่อ flick สำเร็จ (AnimationCurve)
  - Particle ของในกระทะกระเด้ง

Unity API
  - Input.acceleration (ต้อง build ลงมือถือจริง — Editor ไม่มี sensor)
  - Input.compensateSensors = true (Project Settings) ถ้าต้องการ

EVENT 2 — เอียงมือถือเทของ (Tilt pour — น้ำมัน / ไข่)
────────────────────────────────────────────────────────────────────────────────

Concept
  เอียงมือถือช้าๆ → อัตราการเทเพิ่ม (pour rate)
  ของแตกง่าย (ไข่): เอียงเร็วเกิน → แตก → penalty

อ้างอิง pattern จาก coco/SeasoningMinigame (gauge + ideal zone) แต่เปลี่ยน input เป็น tilt

ไฟล์ที่ต้องสร้าง
  pep/Scripts/Input/TiltPourReader.cs
  pep/Scripts/Minigames/Preparation/TiltPourMinigame.cs
  ขยาย pep/Scripts/Recipe/IngredientSO.cs — field เพิ่ม (ดูด้านล่าง)

TiltPourReader.cs
  - CalibrateNeutral() ตอนเริ่ม — เก็บ accel ขณะมือถือตั้งตรง
  - tiltX = accel.x - neutral.x (หรือใช้แกน Z ตาม Screen.orientation)
  - pourRate = Mathf.Clamp01(Mathf.InverseLerp(minTilt, maxTilt, tiltX))
  - tiltVelocity = delta tilt / dt — ใช้เช็คของแตก
  - Editor fallback: ลาก mouse ซ้าย-ขวา แทน tilt

TiltPourMinigame.cs
  - fillAmount += pourRate * pourSpeed * dt (คล้าย SeasoningMinigame.currentFill)
  - UI mock จาก code: Slider gauge + ideal zone rect + ชื่อวัตถุดิบ
  - โหมด isFragile (ไข่):
      if (tiltVelocity > fragileBreakThreshold) → แตก → score ต่ำ / fail step
  - โหมด liquid (น้ำมัน):
      เน้นความแม่นยำใน idealMin–idealMax (เช่น 65–85%)
  - event: OnPourCompleted(float score, bool broken)
  - ใช้ใน PreparationState (เทน้ำมันก่อนผัด) หรือ sub-step ใน Cooking

IngredientSO — field ที่ควรเพิ่ม
  [SerializeField] bool isPourable;
  [SerializeField] bool isFragile;
  [SerializeField] float idealPourMin = 65f;
  [SerializeField] float idealPourMax = 85f;
  [SerializeField] float fragileMaxTiltVelocity = 2.5f;

เชื่อมกับ state machine
  - PreparationState เรียก TiltPourMinigame เมื่อ recipe step ต้องเทของ
  - หรือ RecipeSO เพิ่ม enum step type: Pour, Flick, Chop, ...

EVENT 3 — แมลงสาบวิ่งผ่าน (Random disturbance)
────────────────────────────────────────────────────────────────────────────────

Concept
  ระหว่างเตรียมวัตถุดิบ / หั่นผัก — สุ่มเกิดแมลงสาบวิ่งข้ามโต๊ะ
  ผู้เล่นต้องแตะไล่ก่อนวิ่งถึงเขตวัตถุดิบ → ไม่แตะ = hygiene penalty

ไฟล์ที่ต้องสร้าง
  pep/Scripts/GameplayEvents/KitchenDisturbanceManager.cs
  pep/Scripts/GameplayEvents/CockroachRunner.cs
  pep/Scripts/GameplayEvents/DisturbanceEventSO.cs (optional — config สุ่ม)
  pep/Prefabs/GameplayEvents/Cockroach.prefab (placeholder — ทีม art ทำทีหลังได้)

KitchenDisturbanceManager.cs
  - Subscribe GameStateMachine.OnStateEntered
  - Active เฉพาะ PepGameState.Preparation และ PepGameState.Chopping
  - Coroutine RandomSpawnLoop:
      wait Random.Range(minInterval, maxInterval)
      if (Random.value < spawnChance) SpawnCockroach()
  - SerializeField: minInterval=8s, maxInterval=25s, spawnChance=0.35
  - จำกัด concurrent: สูงสุด 1 ตัวบนจอ
  - OnStateExited → หยุด spawn + destroy active

CockroachRunner.cs
  - waypoint 2-4 จุด (RectTransform บน UI mock หรือ Transform ใน world — code รับ array)
  - MoveTowards ด้วย speed
  - OnPointerClick / raycast tap → PlaySquash() → destroy + bonus hygiene
  - ถ้าวิ่งถึงจุดสุดท้าย (เขตวัตถุดิบ) → OnContaminated() → penalty
  - penalty: ScoringManager.ReportStepScore("pep/Cockroach", "Hygiene", -15f) หรือ clamp 0

UI mock (PEP ทำใน code)
  - สร้าง panel overlay บน Canvas มี Image สี่เหลี่ยมสีน้ำตาลแทนแมลงสาบ (ก่อนมี art)
  - หรือ runtime quad + Button component สำหรับ tap

เชื่อมกับ minigame อื่น
  - PreparationState / Chopping adapter ไม่ต้องรู้เรื่องแมลงโดยตรง
  - DisturbanceManager เป็น singleton ข้าม phase ฟัง state machine อย่างเดียว
